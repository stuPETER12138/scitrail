## 1. 定稿：A+D 混合架构

### 1.1 分工原则

| 层 | 来源 | 职责 |
|---|---|---|
| 骨架 | 方案 A | 课题 / 任务 / 收件箱 / DDL / 里程碑 / 今日视图 / 极简界面 |
| 流水 | 方案 D | 轨迹页：实验、文献、报销、组会、笔记统一为 entry 条目 |
| 轨迹交互 | DeepSeek Harness 借鉴 | 账本 + 时序总览 + 检查器 + 跟随最新（见第 2 节） |
| 成长 | 方案 E 的子集 | P1 模块（论文/成果对照等）将来按 E 的表结构追加 |

### 1.2 核心架构决策

1. **轨迹是投影，不是副本**（最重要的决策，来自 dsh 的"纯投影"思想）：轨迹页的数据是 `entry + task 完成事件 + DDL 节点` 的 **SQL UNION 查询结果**，不单独建"活动表"。数据只有一份，各归各表，轨迹页只负责按时序合并渲染。
2. **任务与条目分开建模**：任务有状态机（待办/进行中/完成/放弃）和重复规则，进 `task` 表；条目是"已发生的事实的记录"（实验/文献/报销/组会/笔记），append 为主，进 `entry` 表。两者的联系：条目可"转为任务"；任务完成后自动出现在轨迹里。
3. **速录一条语法，按前缀分流**：`实/文/钱/会/记` 前缀 → entry；`任` 前缀或无前缀（任务页语境）→ task。
4. **单人单进程**：Tauri 2 桌面应用——Rust 内核 + 系统 WebView（Windows 用 WebView2），双击 exe 启动，自带原生窗口、托盘与全局快捷键速录。

## 2. 轨迹页设计（借鉴 DeepSeek Harness Trajectory）

参考：[ui-trajectory README](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-trajectory/README.md) · [DeepSeek Harness 官网](https://www.deepseek.com/zh/harness)

### 2.1 借鉴对照表

| dsh Trajectory 概念 | 原设计（dsh 中） | 我们的实现（轨迹页） |
|---|---|---|
| 事件账本 Ledger | Agent 事件按类型分行的账本 | 条目+任务事件的时间流，每条含类型图标、时刻、标题、课题色标 |
| 回合/步骤边界 | turn / step 分隔标记 | **按日分组**："今天 · 10-24 周六 · 5 条" 作为组分隔头 |
| 时序总览 Timing Overview | 账本上方固定时序条，投影每条记录的开始/时长 | **当日时序条**：一天 0~24 时横条，每条记录按时刻落一个刻度点；悬停显示精确时刻；**拖拽框选区间** → 过滤下方账本 |
| 尾部锚定 + 分页加载 | 打开定位最新尾部，向上按页加载 | 打开自动滚到今天末尾；向上滚动按日加载更早（"加载 10-22 及以前"控件） |
| 检查器 Inspector | 点选记录打开详情（token/时长/输入输出） | 点条目 → **右侧检查器抽屉**：全部结构化字段、数据路径（可点"打开目录"）、修改历史、操作按钮 |
| 流式跟随 | 流式时跟随尾部，上滚即暂停 | **跟随最新**开关：开启时新记录自动滚入；上滚浏览历史即自动暂停，不被新记录打断 |
| Summary / Raw 双视图 | 摘要视图与原始 content-block 视图切换 | 条目"卡片 / Markdown 源码"切换（检查器内 + 账本全局开关） |
| 不虚构时间 | 不为未完成记录编造时长 | 没有时刻的补录条目只显示日期标记，不显示假时间 |
| 虚拟化渲染 | 只挂载可见行 | M1 不做（单日条目 <50）；>2000 条时再引入虚拟滚动 |
| 纯投影 | 只读 Session 窗口原始事件，不碰快照 | 轨迹 = UNION 查询投影（见 §4.4），不建副本表 |

## 4. 数据库设计（完整 DDL）

> 公共约定：所有业务表含 `owner INTEGER NOT NULL DEFAULT 1`（课题组化预留）、`deleted_at TEXT`（软删除）、`created_at/updated_at`。时间统一本地时区字符串 `YYYY-MM-DD[ HH:MM[:SS]]`。

```sql
-- ============ 课题 ============
CREATE TABLE project (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,
  type        TEXT NOT NULL DEFAULT '自选',   -- 学位课题/导师纵向/横向/自选/申报
  role        TEXT,                           -- 负责人/核心参与/参与
  status      TEXT NOT NULL DEFAULT '进行中', -- 进行中/暂停/已结题/归档
  color       TEXT,                           -- 前端标识色，如 #e0533d
  start_date  TEXT,
  end_date    TEXT,
  note        TEXT,
  owner       INTEGER NOT NULL DEFAULT 1,
  deleted_at  TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at  TEXT
);

-- ============ 学位里程碑 ============
CREATE TABLE milestone (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  name        TEXT NOT NULL,                  -- 开题/中期/预答辩/送审/答辩/自定义
  target_date TEXT,
  status      TEXT NOT NULL DEFAULT '未开始', -- 未开始/进行中/已完成
  done_at     TEXT,
  note        TEXT,
  owner       INTEGER NOT NULL DEFAULT 1,
  deleted_at  TEXT,
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at  TEXT
);

-- ============ 任务 ============
CREATE TABLE task (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  title        TEXT NOT NULL,
  note         TEXT,
  project_id   INTEGER REFERENCES project(id) ON DELETE SET NULL,   -- NULL=收件箱
  milestone_id INTEGER REFERENCES milestone(id) ON DELETE SET NULL,
  priority     INTEGER NOT NULL DEFAULT 2,    -- 0高 1中 2低
  due_date     TEXT,
  status       TEXT NOT NULL DEFAULT '待办',  -- 待办/进行中/完成/放弃
  repeat_rule  TEXT,                          -- 'weekly:1'=每周一；''=不重复
  completed_at TEXT,                          -- 完成时刻，轨迹投影用
  owner        INTEGER NOT NULL DEFAULT 1,
  deleted_at   TEXT,
  created_at   TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at   TEXT
);
CREATE INDEX idx_task_view    ON task(deleted_at, status, due_date);
CREATE INDEX idx_task_project ON task(project_id);

-- ============ DDL ============
CREATE TABLE ddl (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  name          TEXT NOT NULL,
  category      TEXT,                    -- 会议截稿/期刊返修/奖学金/竞赛/答辩窗口/其他
  due_date      TEXT NOT NULL,           -- 'YYYY-MM-DD' 或 'YYYY-MM-DD HH:MM'
  lead_days     TEXT NOT NULL DEFAULT '7,3,1',
  project_id    INTEGER REFERENCES project(id) ON DELETE SET NULL,
  status        TEXT NOT NULL DEFAULT '生效',   -- 生效/已办结/已取消
  repeat_yearly INTEGER NOT NULL DEFAULT 0,     -- 会议截稿复制下一年
  note          TEXT,
  owner         INTEGER NOT NULL DEFAULT 1,
  deleted_at    TEXT,
  created_at    TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at    TEXT
);
CREATE INDEX idx_ddl_due ON ddl(status, due_date);

-- ============ 轨迹条目（D 主线） ============
CREATE TABLE entry (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  date       TEXT NOT NULL,              -- 业务日期，可补录
  time       TEXT,                       -- 'HH:MM'，可空=未知时刻（不虚构时间）
  kind       TEXT NOT NULL,              -- experiment/literature/expense/meeting/note
  title      TEXT NOT NULL,
  content    TEXT NOT NULL DEFAULT '',   -- Markdown 正文
  project_id INTEGER REFERENCES project(id) ON DELETE SET NULL,
  tags       TEXT NOT NULL DEFAULT '[]', -- JSON 数组，课题外的自由标签
  fields     TEXT NOT NULL DEFAULT '{}', -- JSON，按 kind 的结构化字段（见 4.2）
  refs       TEXT NOT NULL DEFAULT '[]', -- JSON：数据路径/链接，[{label,path}]
  owner      INTEGER NOT NULL DEFAULT 1,
  deleted_at TEXT,
  created_at TEXT NOT NULL DEFAULT (datetime('now','localtime')),
  updated_at TEXT
);
CREATE INDEX idx_entry_date    ON entry(date);
CREATE INDEX idx_entry_kind    ON entry(kind, date);
CREATE INDEX idx_entry_project ON entry(project_id);

CREATE VIRTUAL TABLE entry_fts USING fts5(
  title, content, content='entry', content_rowid='id', tokenize='unicode61'
);
-- 同步触发器（entry INSERT/UPDATE/DELETE → entry_fts）

CREATE TABLE entry_history (
  id        INTEGER PRIMARY KEY AUTOINCREMENT,
  entry_id  INTEGER NOT NULL REFERENCES entry(id) ON DELETE CASCADE,
  snapshot  TEXT NOT NULL,               -- 修改前完整 JSON 快照
  saved_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- ============ 周报存档 ============
CREATE TABLE weekly_report (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  week_start   TEXT NOT NULL,            -- 周一日期，唯一
  content      TEXT NOT NULL,            -- 生成/编辑后的 Markdown
  generated_at TEXT,
  edited_at    TEXT,
  owner        INTEGER NOT NULL DEFAULT 1,
  deleted_at   TEXT
);
CREATE UNIQUE INDEX idx_weekly ON weekly_report(week_start);

-- ============ 配置与备份 ============
CREATE TABLE setting (
  key   TEXT PRIMARY KEY,
  value TEXT NOT NULL                    -- JSON 值
);
CREATE TABLE backup_log (
  id          INTEGER PRIMARY KEY AUTOINCREMENT,
  file        TEXT NOT NULL,
  size_bytes  INTEGER,
  status      TEXT NOT NULL DEFAULT 'ok',
  created_at  TEXT NOT NULL DEFAULT (datetime('now','localtime'))
);

-- ============ 任务全文搜索（P1 视需要） ============
CREATE VIRTUAL TABLE task_fts USING fts5(
  title, note, content='task', content_rowid='id', tokenize='unicode61'
);
```

### 4.2 entry.fields 按 kind 的 JSON 结构

| kind | fields 键 | 说明 |
|---|---|---|
| experiment | purpose 方针 / params 参数 / conditions 条件 / sample 样品编号 / device 设备 / conclusion 结论 / followup 后续 | 30 秒表单只强制 title + params |
| literature | authors / year / venue / doi / note 一句话笔记 | |
| expense | amount 金额 / reason 事由 / status 垫付中/已提交/已到账 | |
| meeting | attendees / topic / advisor_feedback 导师意见 | |
| note | （空，用 content） | |

前端按 kind 渲染不同录入表单；后端不校验 fields 内部结构（保持松散，检索靠 title/content/tags）。

### 4.3 周报生成逻辑

拉取 `[week_start, week_start+7)` 内：完成任务（title、project）+ 各 kind 条目数与标题列表 + 下周到期任务/DDL → 拼装 Markdown 模板 → 存 weekly_report（可反复重生成覆盖）。

### 4.4 轨迹投影查询（服务端 services/trajectory.py）

```sql
SELECT 'entry' AS src, e.id, e.date || ' ' || COALESCE(e.time,'') AS at,
       e.kind, e.title, e.project_id
FROM entry e WHERE e.deleted_at IS NULL AND e.date BETWEEN :from AND :to
UNION ALL
SELECT 'task_done', t.id, t.completed_at, 'task', t.title, t.project_id
FROM task t WHERE t.deleted_at IS NULL AND t.status='完成'
  AND substr(t.completed_at,1,10) BETWEEN :from AND :to
UNION ALL
SELECT 'ddl', d.id, d.due_date, 'ddl', d.name, d.project_id
FROM ddl d WHERE d.deleted_at IS NULL AND d.status='生效'
  AND substr(d.due_date,1,10) BETWEEN :from AND :to
ORDER BY at DESC;
```

按日分组由 API 层完成（`{days:[{date, items:[…]}]}`），每种 src 附带完整负载（entry 全字段 / task 摘要 / ddl 摘要）。

### 4.5 速录语法（services/quick_parse.py）

```
[类型前缀] 内容 #课题 *标签 !优先级 [日期] [时间]
```

- 前缀：`实`=experiment，`文`=literature，`钱`=expense，`会`=meeting，`记`=note，`任`=task；
- `#课题` 模糊匹配 project.name（匹配不上 → 不关联，提示可新建）；
- `*标签` 自由标签（可多个）；`!高/!中/!低` 优先级（仅 task）；
- 日期词：`今天/明天/后天/周X/MM-DD`；时间：`HH:MM` 或 `21点15`；
- 解析结果先回显预览（高亮各 token），回车确认保存；
- 解析失败不报错：整段作为 title，其余留空（可后补）。

示例：`实 完成#催化 1150℃×2h 明天 9:00` → entry(kind=experiment, project=催化, date=明天, time=09:00, title=完成 1150℃×2h)。

### 4.6 备份一致性（重要实现约束）

SQLite 开 WAL 后**直接复制 .db 文件可能拿到不一致快照**（WAL 未 checkpoint、写入进行中）。备份一律用 `VACUUM INTO 'backups/scitrace-YYYYMMDD-HHMM.db'`（在线一致性快照，顺带压缩），禁止裸拷贝；恢复 = 关闭连接 → 替换文件 → 重启应用。全量导出 JSON 是第二层人类可读备份，与 .db 快照互补。

## 5. API 设计（Tauri Command，前端 invoke 调用）

下表"端点"即 Tauri 命令，统一 snake_case（`GET /tasks` → `invoke('list_tasks')`，POST → `create_*`，PUT → `update_*`，DELETE → `delete_*`），出入参全部是 serde 结构体，无 HTTP 层。

| 组 | 命令 | 说明 |
|---|---|---|
| auth | unlock · lock | 口令解锁（argon2 校验），本次运行免密 |
| projects | GET/POST /projects · GET/PUT/DELETE /projects/{id} | 列表带"近 7 天动态数"聚合 |
| tasks | GET /tasks?view=today\|inbox\|board\|project&project_id= · POST /tasks · PUT/DELETE /tasks/{id} · POST /tasks/{id}/done | 完成即写 completed_at |
| quick | POST /quick-parse · POST /quick-save | 解析预览 / 确认保存 |
| entries | GET /entries?from&to&kind&project_id&q(FTS) · POST /entries · PUT/DELETE /entries/{id} · GET /entries/{id}/history | 修改前自动存 entry_history |
| trajectory | GET /trajectory?from&to&day_page=14 | §4.4 投影，按日分组 |
| ddls | CRUD 同 tasks · POST /ddls/{id}/rollover | rollover=复制下一年 |
| milestones | CRUD | |
| weekly | POST /weekly/generate · GET /weekly?week_start · PUT /weekly/{id} | |
| dashboard | GET /dashboard | 今日任务/倒计时/课题卡片/本周统计一次取齐 |
| search | GET /search?q | 跨 entry_fts+task_fts 联合，按类型分组返回 |
| stats | GET /stats?from&to&project_id | 回顾页一次取齐：KPI（累计条目/完成任务/实验数/连续记录天数 当前+最长）、逐日计数（热力图用，GROUP BY date 的 UNION 聚合）、趋势序列（按类型）、课题投入分布 |
| settings | GET/PUT /settings · POST /backup/run · GET /backup/list · POST /backup/restore · GET /export?format=json\|md | |

约定：软删除（delete_* 命令置 deleted_at）；错误以中文消息返回（`Result<_, String>`）；分页仅轨迹/搜索需要（按日/按 20 条）。

| /ddl | DDL | 未来 90 天时间轴 + 已过期红顶 + rollover 按钮 |
| /weekly | 周报 | 生成器 + 历史存档 + 导出 .md/复制 |

| /settings | 设置 | 口令修改 · 备份（立即备份/列表/恢复）· 全量导出 · 里程碑维护 · 默认值 |

### 6.2 关键组件

- `QuickCapture`（全局，⌘K / Ctrl+K 呼出）：语法解析回显 → 保存；上下文感知默认前缀（轨迹页默认记、任务页默认任）；
- `DayStrip`：当日时序条（刻度=类型色，悬停 tooltip，拖拽框选→回调过滤）；
- `Ledger` + `LedgerDayGroup` + `TrajectoryRow`：按日分组账本，向上逐日加载，跟随最新开关；
- `InspectorDrawer`：条目检查器（字段渲染按 kind、refs 路径"打开目录"、历史列表、转为任务/编辑）；
- `EntryForm`（分 kind 的 30 秒表单，字段全部可空）；
- `TaskItem` / `TaskBoard` / `DdlCountdown` / `ProjectChip`（课题色标，全局复用）；
- `KpiStrip` / `HeatmapCalendar`（SVG 自绘 53×7 网格，不引图表库）/ `TrendChart`（SVG 折线）。连续记录天数定义：从今天往前，每天至少 1 条 entry 或完成 1 个任务；连续天数 KPI 同步贴到今日页。

### 6.3 设计令牌（styles/tokens.css）

极简清单风：白底/暗色双主题；正文 14px；侧栏 200px；课题色仅出现在小色点与 chip，不大面积用色；红色只给逾期与 !高。

### 6.4 快捷键与全局速录小窗

| 键 | 行为 |
|---|---|
| Ctrl+K（全局，任何应用前可用） | 唤起**速录小窗**：独立无边框置顶小窗（约 320×140），语法同 §4.5，Enter 保存后自动关闭，Esc 取消；不抢主窗口状态 |
| Ctrl+K（应用内） | 聚焦当前页速录框 |

### 6.5 首次运行引导

三步向导（均可跳过）：① 设置解锁口令 → ② 创建首个课题（示例：学位课题）→ ③ 载入《需求报告》2.5 的默认学位里程碑模板（开题/中期/预答辩/送审/答辩，日期按 2027 秋入学推算，全部可改）。首次运行即写 setting 表（口令哈希、引导完成标记）。

## 9. 开发约定

- Git：`main` 单分支 + conventional commits（feat/fix/docs…）；数据目录不入库；
- 迁移：改模型必写 rusqlite_migration 迁移，禁止手改库；
- 测试：quick_parse、trajectory、weekly 三个纯逻辑服务必须有 cargo test（内存 SQLite + 迁移作为测试夹具）；
- 文案：全中文；错误消息可读（"课题'催化'不存在，已按未关联保存"）；
- 开源与 CI（GitHub）：**CI 必做**——push 触发 Actions：`cargo fmt --check` + `cargo clippy -D warnings` + `cargo test` + `vue-tsc --noEmit` + 前端构建（rusqlite bundled 需在干净的 windows-latest 上编译通过才算真通过）；**CD 轻量做**——打 tag（v*）触发 tauri-action 构建 Windows 安装包并自动挂 GitHub Release；不做自动更新器与多平台矩阵（将来加一行 matrix 即可）；无签名证书时 Windows SmartScreen 会警告，个人项目先忽略；
- 许可证 MIT（担心闭源改卖可换 GPL-3.0）；README 中英双语一句话简介 + 界面截图（M1 出界面后补）。
