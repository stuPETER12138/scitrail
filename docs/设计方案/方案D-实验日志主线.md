# 方案 D · 实验日志主线（eLabFTW / Logseq 式）

| 一句话定位 | 以"天"为单位流水记录科研：实验、任务、文献都是日志条目，项目感和统计从日志里长出来 |
|---|---|
| 交互重心 | 每日日志时间线 + 全文搜索 |
| 数据范式 | 统一条目表（entry，append-only 倾向）+ FTS 全文索引 |
| MVP 工作量 | 约 7~10 个集中开发日 |
| 成长路径 | ★★★★ 条目表可与方案 A/E 的表共存，混合无冲突 |

---

## 1. 核心理念

- 工科博士生的真实日常不是"管理项目"，而是**每天做实验、读文献、改代码**——本方案把这三种动作统一为"往今天的日志里记一条"；
- 一条日志（entry）= 一个最小工作单元，带类型（实验/任务/文献/纪要/开销）、时间、内容、标签；
- **项目感靠标签**：`#催化` `#论文A` 就是课题，不建独立的项目对象（或仅建极薄的别名表）；
- 统计和周报不是"填写出来的"，是**聚合出来的**：本周日志按类型一卷就是周报，按月一卷就是学期总结；
- 借鉴 eLabFTW 的核心信念：**记录在先、不可篡改、随时可搜**——实验记录默认保留修改历史。

## 2. 借鉴的开源项目

| 项目 | 借鉴点 |
|---|---|
| [eLabFTW](https://github.com/elabftw/elabftw) | 开源电子实验记录本（ELN）的事实标准：实验条目带时间戳与修改痕迹、步骤清单、标签、关联资源库；"Experiment + Database"双区结构 |
| [Logseq](https://github.com/logseq/logseq) | Daily Journal 工作流：每天一页，想到什么记什么，靠双链和标签事后组织——"先记录后整理" |
| [Trilium Notes](https://github.com/TriliumNext/trilium) | SQLite 单库存储 + day notes（自动生成每日笔记）；笔记属性模型（标签/关系当作属性挂在笔记上） |

## 3. 界面设计

### 3.1 布局线框（主窗口：今日日志）

```
┌──────────────────────────────────────────────────────────────────┐
│ 📅 2026-10-23 周五          [⌘K 速记: 实 完成#催化 参数1150℃]     │
├──────────────────────────────────────────────────────────────────┤
│ 09:12 🧪 实验 #催化  预烧结梯度 1150℃×2h                          │
│        参数: 升温5℃/min 数据: \\nas\xps\1023                      │
│        →待办: 与1100℃样品对比XPS                                  │
│ 11:40 ✅ 任务 #论文A  回复审稿意见第2条（用时50min）               │
│ 14:05 📖 文献 [Sun 2026 JMCA] MoS2边界缺陷调控，方法可借鉴         │
│ 16:30 💰 报销 #催化  移相器 ¥380（垫付中）                        │
│ ───────────────────────────────────────────────────────────────  │
│ ⏳ 今日倒计时: ACSAMI全文 12天 | 组会 下周一                       │
│ [生成周报草稿]  [生成明日计划(从#待办)]                            │
├──────────────────────────────────────────────────────────────────┤
│ 侧栏: 📆 日历缩略 | #标签云(#催化64 #论文A31) | 🔍全文搜索          │
└──────────────────────────────────────────────────────────────────┘
```

### 3.2 页面清单（7 页）

今日/任意日日志（核心页）/ 搜索（FTS 全库）/ 标签视图（=课题页：该标签全部条目时间线）/ 倒计时墙 / 周报助手（按周聚合）/ 回顾（月/学期统计）/ 设置

### 3.3 关键交互

- **速记语法带类型前缀**：`实/任/文/纪/钱` 开头决定条目类型，`#`打标签，一句话记完；
- **条目内 →待办 语法**：实验记录里写的"→待办：对比XPS"一键提取为正式任务条目；
- **搜索是第一入口**："上次 1150℃ 那组"直接 FTS 全文搜——本方案最大的使用快感来源；
- **补录自然**：日历选任意日期即可插入条目，系统不关心你是不是今天记的；
- 修改条目不清空旧文：edited_at 更新 + 旧内容进历史（eLabFTW 式留痕，轻量实现）。

### 3.4 视觉风格

Logseq/日记风：时间线为主轴、条目左侧类型色点、正文即笔记；无表格感，全部是"记录流"；标签用彩色 chip。

## 4. 数据库设计

### 4.1 表清单（6 张）

| 表 | 职责 |
|---|---|
| entry | **万能条目**：实验/任务/文献/纪要/开销统一存 |
| tag + entry_tag | 标签（=课题/论文/任意主题） |
| entry_history | 条目修改历史（轻量留痕） |
| ddl | 独立 DDL（倒计时墙） |
| project_alias | 标签→课题的别名/备注表（极薄，可选） |
| setting | 配置 |

### 4.2 核心表 DDL（SQLite）

```sql
CREATE TABLE entry (
  id          INTEGER PRIMARY KEY,
  date        TEXT NOT NULL,          -- 业务日期（可补录）
  time        TEXT,
  kind        TEXT NOT NULL,          -- experiment/task/literature/note/meeting/expense
  title       TEXT NOT NULL,
  content     TEXT DEFAULT '',        -- Markdown
  refs        TEXT DEFAULT '[]',      -- JSON: 数据路径/链接/关联entry id
  status      TEXT,                   -- 仅 task 类: 待办/完成；其余 NULL
  created_at  TEXT DEFAULT (datetime('now')),
  edited_at   TEXT
);
CREATE INDEX idx_entry_date ON entry(date);
CREATE INDEX idx_entry_kind ON entry(kind, date);

CREATE TABLE tag (
  id   INTEGER PRIMARY KEY,
  name TEXT UNIQUE NOT NULL          -- #催化 #论文A #国自然
);
CREATE TABLE entry_tag (
  entry_id INTEGER REFERENCES entry(id) ON DELETE CASCADE,
  tag_id   INTEGER REFERENCES tag(id) ON DELETE CASCADE,
  PRIMARY KEY (entry_id, tag_id)
);

CREATE TABLE entry_history (
  id        INTEGER PRIMARY KEY,
  entry_id  INTEGER REFERENCES entry(id) ON DELETE CASCADE,
  snapshot  TEXT,                    -- 修改前的 JSON 快照
  saved_at  TEXT DEFAULT (datetime('now'))
);

CREATE VIRTUAL TABLE entry_fts USING fts5(title, content, content='entry');
```

### 4.3 设计取舍

- **一张 entry 表扛所有类型**：换来"记录永远只要一个入口"；代价是字段松（实验参数在 content 或 refs 里），类型化的筛选/统计靠 kind + 标签，够用但不精确；
- **课题不建实体**：`#催化` 即课题；副作用是改名要全量替换标签，所以留一张极薄的别名备注表兜底；
- **FTS 是一等公民**：从第一天就建全文索引，"可搜"与"可记"同等重要。

## 5. 对需求报告的覆盖度

| 需求模块 | 覆盖情况 |
|---|---|
| 实验记录 | ✅ 最强（含留痕、补录、待办提取） |
| 任务 / 收件箱 / 周报 | ✅ 完整（任务=entry 子集；周报=按周聚合） |
| 文献清单 / 报销 | ✅ 顺手覆盖（都是 entry 类型） |
| 课题（容器） | ⚠️ 弱化为标签（无课题详情聚合页，只有标签时间线） |
| DDL / 里程碑 | ✅ 完整（独立表+倒计时墙） |
| 成果对照 / 论文流水线 | ⚠️ 需后补（成果适合独立成表，不塞 entry） |
| 仪表盘 | ⚠️ 偏"今日日志"，统计视图要二期 |

## 6. 优缺点与风险

**优点**：与工科"天天记实验"的习惯**契合度五案最高**；录入摩擦最小（比 A 还少一层结构心智）；回溯与搜索体验最好；周报/学期总结是免费的副产品。

**缺点**："项目管理感"最弱——课题没有面板、没有进度条，全靠标签纪律；看板/甘特这类视图需要二期补。

**风险**：标签失控（记了一个月后 `#催化` `#催化课题` `#cat` 并存）——需要标签自动补全 + 定期合并工具，设计时就要排进去。

## 7. 工作量估计

日志页+速记+entry 表+FTS 搜索：5~7 天；标签体系+倒计时墙：+2 天；周报聚合+回顾：+2 天。

## 8. 何时选它

日常工作**以实验和记录为绝对主体**、相信"先记下来再说"、检索回忆需求强——选 D。它也可以作为"实验模块"并入方案 A：A 的任务骨架 + D 的 entry 表，两张核心表互不冲突。
