## 1. 引言

### 1.1 背景与目标

博士生的科研工作通常横跨多个项目（导师课题、自选课题、奖学金/竞赛申报等），并伴随大量周期性事务：组会汇报、周报月报、中期检查、结题材料、经费报销、论文投稿跟踪。这些信息目前大多散落在聊天记录、Excel、邮箱和记忆中，缺少统一管理，常见痛点：

- **进度不透明**：导师与学生之间信息不对称，项目实际进展靠口头汇报；
- **关键节点易遗忘**：中期检查、结题截止、报销截止等日期没有统一提醒；
- **经费是一本糊涂账**：花了多少、还剩多少，需要手工翻记录；
- **成果与项目脱节**：论文、专利散落各处，写总结、奖助申报、毕业材料时需要到处翻找。

**系统目标**：为博士生个人及课题组/院系提供一个覆盖"项目立项 → 执行 → 结题 → 成果沉淀"全生命周期的管理平台，让进度、任务、经费、成果、文档在同一个地方**可查、可管、可提醒**。

### 1.2 术语定义

| 术语 | 含义 |
|---|---|
| 纵向项目 | 各级政府/基金委立项的课题（如国家自然科学基金、省基金） |
| 横向项目 | 企业委托的技术开发/咨询课题 |
| 里程碑 | 项目中的关键时间节点（开题、中期检查、投稿、结题等） |
| 结题 | 项目按合同/任务书要求完成并提交结题材料、通过验收 |
| MVP | 最小可用版本（Minimum Viable Product），只包含 P0 功能 |

### 1.3 目标用户与角色

| 角色 | 说明 | 主要诉求 |
|---|---|---|
| 博士生 | 核心使用者 | 管理自己的项目、任务、汇报、报销、成果 |
| 导师 / 课题组负责人 | 指导与监督者 | 掌握所辖学生整体进度，审批立项/变更/结题 |
| 管理员 | 系统维护 + 院系科研管理 | 用户管理、数据字典、全院统计 |
| （可选扩展）硕士生、博士后 | 复用"学生"角色 | 与博士生一致 |

### 1.4 假设与约束

- 使用规模：从一个课题组（5–30 人）到院系级（约 200–500 用户）；
- 部署形式：校内服务器或云服务器，浏览器访问；暂不做原生 App，移动端通过浏览器适配；
- MVP 阶段使用本地账号密码登录，后续可选对接学校统一身份认证（CAS/OAuth）；
- 系统不承载实验数据本体，只做索引与链接（实验数据应由专业工具管理）。

## 2. 总体描述

### 2.1 系统定位（三层）

1. **个人工具**：博士生管理自己所有项目和任务 —— 个人版核心；
2. **课题组协作**：导师查看学生进度、汇报，处理审批 —— 课题组版；
3. **院系管理**：管理员统计全院项目、经费、成果 —— 管理版。

MVP 以"个人工具 + 导师查看"为主，院系管理在后续阶段完善。

### 2.2 角色权限矩阵（概要）

| 功能 | 博士生 | 导师 | 管理员 |
|---|:---:|:---:|:---:|
| 管理自己的项目/任务/汇报 | ✓ | ✓ | — |
| 查看所指导学生的项目与汇报 | 仅自己 | ✓ | ✓ |
| 发起立项/变更/结题申请 | ✓ | ✓ | — |
| 审批（立项/变更/结题） | 提交方 | 初审 | 终审（可选） |
| 录入报销记录 | ✓ | 审核 | 查看/导出 |
| 用户与字典管理 | ✗ | ✗ | ✓ |

> 权限校验必须在服务端强制执行，前端仅做展示控制。

### 2.3 项目全生命周期（核心业务流）

```
草稿 → 申请中 → 进行中 → 中期检查 → 结题申请 → 已结题 → 归档
        │           │             │
        └─ 驳回/退回 └─ 变更（延期 / 成员调整 / 预算调整）
                                   └─ 终止（中止、撤项）
```

每个状态对应：需提交的材料、审批人、系统自动提醒的时间点。所有状态变更留痕（操作日志 + 项目动态时间线）。

## 3. 功能需求

优先级定义：**P0 = MVP 必须**，**P1 = 第一阶段应该有**，**P2 = 可选扩展**。

| 模块 | 优先级 |
|---|:---:|
| 3.1 用户与权限管理 | P0 |
| 3.2 项目管理（核心） | P0 |
| 3.3 任务与进度管理 | P0 |
| 3.4 进度汇报（周报/月报/组会） | P0 |
| 3.5 提醒与通知 | P0 |
| 3.6 个人仪表盘 | P0 |
| 3.7 文档管理 | P1 |
| 3.8 审批流程 | P1 |
| 3.9 经费管理 | P1 |
| 3.10 研究成果管理 | P1 |
| 3.11 统计报表 | P1 |
| 3.12 系统管理 | P1 |
| 3.13 可选扩展 | P2 |

### 3.1 用户与权限管理（P0）

- 登录/注册：账号 + 密码，支持记住登录；密码加密存储；
- 个人资料：姓名、学号/工号、院系、专业、年级、研究方向、头像、联系方式；
- 角色管理：学生、导师、管理员三类角色（RBAC）；
- **师生关系绑定**：建立导师 ↔ 学生的指导关系（一名学生一名主导师，可有多位合作导师）；
- 密码修改与找回。

### 3.2 项目管理（P0，系统核心）

- **项目建档**：名称、编号、类型（纵向/横向/校级/自选）、来源（如国自然、省基金、企业委托）、起止时间、预算金额、本人角色（负责人/参与人）；
- **生命周期状态管理**：按 2.3 的状态机流转，支持驳回与终止；
- **项目成员管理**：添加成员、分配职责、成员变更记录；
- **项目列表**：按状态/类型/时间筛选，支持搜索与排序；
- **项目详情页**：聚合展示基本信息、任务、汇报、经费、成果、文档、审批与动态时间线；
- **项目归档**：结题后一键归档，归档项目只读但可随时查阅；
- 历史项目支持 Excel 批量导入（P1）。

### 3.3 任务与进度管理（P0）

- **任务**：标题、描述、负责人、优先级（高/中/低）、截止日期、状态（待办 / 进行中 / 已完成 / 受阻）；
- **里程碑**：项目内关键节点（开题、中期、投稿、结题），里程碑下可挂多个任务；
- **两种视图**：看板（按状态拖拽）、列表（按时间/负责人排序）；甘特图列为 P2；
- **进度自动汇总**：任务/里程碑完成度自动折算为项目整体进度百分比；
- **受阻机制**：任务标记"受阻"时必须填写原因，导师端可见 —— 这是师生沟通的关键设计。

### 3.4 进度汇报（P0）

- **周报/月报**：模板化填写（本周工作、下周计划、问题与需协调事项），支持一键引用本周已完成任务生成草稿；
- **组会记录**：汇报日期、主题、内容纪要、附件（PPT）、导师评语；
- **导师端**：查看/批量查看所辖学生最新汇报，可标记已读、写点评、催交。

### 3.5 提醒与通知（P0）

- 站内消息中心 + 未读角标；
- 触发场景：任务/里程碑临近截止（提前 N 天，可配置）、逾期、审批待办、汇报催交、项目状态变更；
- 邮件提醒（P1），后续可扩展对接企业微信/钉钉/飞书。

### 3.6 个人仪表盘（P0）

- 学生首页：我的项目卡片（含进度条）、今日/本周待办、临近截止事项、本周汇报是否已提交；
- 导师首页：学生进度总览（红黄绿灯）、逾期任务、待审批事项、最近汇报。

### 3.7 文档管理（P1）

- 项目附件：申报书、任务书、合同、中期报告、结题报告等，按项目归类存储；
- 版本管理：同名文档可上传新版本并保留历史；
- 在线预览常见格式（PDF / Word / 图片）；可见权限跟随项目。

### 3.8 审批流程（P1）

- 内置三类审批：**立项申请**、**项目变更**（延期/成员调整/预算调整）、**结题申请**；
- 流程：学生提交 → 导师审批 →（可选）管理员终审；
- 审批意见留痕；审批通过后自动变更项目状态/对应字段。

### 3.9 经费管理（P1）

- 预算科目对齐常见科研经费分类：设备费、材料费、测试化验加工费、差旅费、出版/文献/知识产权费、劳务费、其他；
- **报销记录**：日期、金额、科目、用途说明、票据附件、关联项目；
- **预算执行**：已用 / 剩余 / 执行率，超预算预警；
- 按项目/时间段导出 Excel 台账。

### 3.10 研究成果管理（P1）

- 成果类型：期刊论文、会议论文、专利（发明/实用新型）、软件著作权、竞赛获奖、标准；
- 字段：题目、作者排序（本人第几作者）、期刊/会议名称、状态（撰写中 / 投稿中 / 返修 / 录用 / 已发表）、日期、DOI/链接、关联项目；
- 按学生/项目/年度统计成果数量；
- 一键导出个人成果列表（用于奖助申报、年度总结、毕业材料）。

### 3.11 统计报表（P1）

- 项目数量与状态分布、按类型/院系维度统计；
- 经费执行率排行与趋势；
- 成果年度趋势、师生产出统计；
- 报表支持导出（Excel / 图片）。

### 3.12 系统管理（P1）

- 用户管理：增删改查、重置密码、Excel 批量导入；
- 数据字典维护：项目类型、经费科目、成果类型等可配置项；
- 操作日志：关键操作留痕，可按人/时间/模块查询；
- 数据备份：定期自动备份，支持手动导出。

### 3.13 可选扩展（P2）

- **文献管理**：题录收藏与项目关联（建议初期直接用 Zotero，系统内只存链接）；
- **日历集成**：里程碑导出 iCal，或推送至飞书/钉钉/企业微信日历；
- **实验记录索引**：登记实验记录本编号/存放位置，不存数据本身；
- 移动端小程序、开放 API。

## 4. 非功能需求

| 类别 | 要求 |
|---|---|
| 性能 | 常规页面响应 ≤ 2 秒；列表分页加载；支持约 100 人同时在线 |
| 安全 | 密码加密存储（bcrypt 等单向散列）；RBAC 权限在服务端强制校验；上传文件限制类型与大小；防 SQL 注入 / XSS；敏感操作二次确认 |
| 可用性 | 全中文界面；高频操作（记任务、写周报）≤ 3 次点击可达；表单校验给出明确中文提示 |
| 兼容性 | Chrome / Edge 最新两个大版本；页面适配 1366×768 及以上；移动端浏览器至少可查看 |
| 可维护性 | 代码使用 Git 管理；数据库结构变更脚本化；提供部署与运维文档 |
| 数据可靠性 | 每日自动备份数据库与附件，备份保留 ≥ 30 天；恢复流程需演练验证 |

## 5. 数据实体概要

主要实体及关系（详细字段与 ER 图在数据库设计阶段输出）：

- **用户 User**（角色、个人资料）；
- **师生关系 Relation**（导师 ↔ 学生）；
- **项目 Project**（类型、来源、状态、起止时间、预算、负责人）；
- **项目成员 ProjectMember**（项目 ↔ 用户，项目内职责）；
- **里程碑 Milestone**（所属项目、计划日期、状态）；
- **任务 Task**（所属项目/里程碑、负责人、状态、优先级）；
- **汇报 Report**（周报/月报/组会；作者、内容、附件、导师批注）；
- **附件 Attachment**（多态关联：项目/任务/汇报/报销/成果）；
- **报销 Expense**（项目、科目、金额、凭证、审核状态）；
- **成果 Achievement**（类型、元数据、关联项目、作者排序）；
- **审批 Approval**（类型、提交人、当前节点、结论、意见）；
- **通知 Notification**（接收人、类型、内容、已读状态）；
- **操作日志 AuditLog**。

## 7. 技术选型建议（供决策，不影响需求范围）

| 方案 | 组合 | 适用场景 |
|---|---|---|
| A（推荐） | Vue 3 + Element Plus 前端，Spring Boot 或 FastAPI 后端，MySQL 数据库，校内/云服务器部署 | 课题组到院系规模，需要长期维护 |
| B（轻量起步） | SQLite + FastAPI + Vue，单机或 NAS 部署 | 仅个人/极小团队使用，后续可平滑迁移到 MySQL |
| C（不写代码） | 飞书多维表格 / Notion 搭建 | 快速验证流程，但审批流与权限粒度受限 |

> 建议：若确认自建，先用方案 A/B 之一实现 MVP，跑通核心流程后再决定部署形态。

## 8. 开发里程碑建议

| 阶段 | 内容 | 验收要点 |
|---|---|---|
| M1 · MVP（约 3–4 周） | 登录与角色、项目建档与状态流转、任务/里程碑、个人仪表盘、基础通知 | 学生可完整管理一个项目的基本信息与任务 |
| M2 · 协作 | 进度汇报、导师视图、审批流、文档上传 | 导师可查看学生进度并完成一次结题审批 |
| M3 · 完整版 | 经费、成果、统计报表、系统管理 | 全部 P0/P1 功能可用 |
| M4 · 打磨 | 性能优化、邮件提醒、甘特图等 P2 项 | 按需排期 |

## 9. 风险与应对

| 风险 | 应对 |
|---|---|
| 需求边界扩散（尤其文献管理容易做成大坑） | MVP 严格限定 P0，扩展项独立排期 |
| 学校对数据安全/私有化有要求 | 部署前确认校内规定（是否要求私有部署、等保要求） |
| 用户弃用（学生嫌填写麻烦） | 周报支持从任务一键生成；仪表盘信息密度优先于功能堆砌 |
| 历史数据迁移 | 提供 Excel 批量导入模板 |

## 10. 待确认问题清单

> 以下问题直接影响实现范围，建议在进入设计前确认：

1. **使用范围**：仅自己个人使用，还是整个课题组/院系共用？（决定是否需要完整审批流与管理端）
2. 是否需要对接学校**统一身份认证**？
3. 经费数据是否需要与学校**财务系统对账**，还是纯手工记录即可？
4. 导师是否需要**移动端**（小程序/公众号）查看进度？
5. 是否已有**历史数据**（项目、成果）需要批量导入？
6. 部署环境：校内服务器、个人云服务器，还是先本地运行？
