## 1. 引言与定位

### 1.1 使用场景

系统当前**仅本人使用**，定位是一个跑在本机的"个人科研操作系统"：管理的对象是**一个博士生的全部科研事务**，而不是一个课题组。

因此 v0.1 中面向组织协作的能力（多角色权限、审批流、导师端、催交、用户管理）全部裁剪（差异见第 11 节），省下的开发量全部投向个人高频场景：**速记、实验流水、DDL 倒计时、周报生成、毕业对照**。

### 1.2 系统目标

一句话：**打开系统 10 秒内知道"今天该干什么、最近什么最急"；30 秒内能记完一笔任务/实验/开销；学期末能一键回溯"这学期我干了什么"。**

毕业导向：博士生涯的一切工作最终服务于毕业（学位论文 + 成果要求），系统顶层必须随时能回答三个问题：

1. 距离下一个学位节点还有多久？
2. 毕业成果要求还差什么？
3. 手头每篇论文、每个课题各自进展到哪了？

### 1.3 术语

| 术语 | 含义 |
|---|---|
| 课题（项目） | 一项长期工作的容器：学位课题、导师项目、自选方向、申报事项 |
| 学位里程碑 | 学位论文流程的关键节点：开题、中期、预答辩、送审、答辩 |
| DDL | 外部强加、**不可移动**的截止时间：会议截稿、奖学金申报、答辩窗口等 |
| 实验流水 | 一次实验的结构化简要记录（工科日常工作的基本单元） |
| 收件箱 | 未归类任务的暂存区 |

## 2. 管理方式设计（方法论）

> 本节是 v0.2 的核心：先定"怎么管"，再定"做什么功能"。

### 2.1 三层管理模型：北极星 — 容器 — 流水

```
第 1 层 · 北极星（全局唯一）：毕业主线
    学位里程碑（开题→中期→预答辩→送审→答辩）
    + 毕业成果要求对照 + 毕业倒计时

第 2 层 · 容器（并行 2~5 个）：课题 / 工作流
    导师课题A / 导师课题B(横向) / 自选方向 / 论文投稿 / 申报事项
    —— 每个容器挂着各自的任务、实验、文献、资料

第 3 层 · 流水（日积月累）：记录
    任务 / 实验记录 / 文献 / DDL / 报销 / 资料索引
    —— 只需打标签归属，不强求字段填全
```

关键设计判断：

- **课题是容器，不是流程**。个人使用不需要"立项—审批—结题"的状态机，简化为 `进行中 / 暂停 / 已结题 / 归档` 四态。
- **任务可以不属于任何课题**。临时琐事直接进收件箱，周五回顾时再归类，不强迫现场分类。
- **DDL 与里程碑分开**。里程碑是计划（可调整），DDL 是"法律"（不可动）。混在一起会让真正的死线被淹没。

### 2.2 一周工作流（系统围绕这个节奏设计）

| 时点 | 动作 | 系统支持 |
|---|---|---|
| 每天早上 | 打开仪表盘 | 今日任务 + 未来 7 天 DDL/里程碑倒计时 |
| 实验当天 | 顺手记实验流水 | 30 秒表单：目的/参数/数据路径/结论 |
| 随时 | 琐事进收件箱 | 全局快速录入（快捷键 + 速记语法） |
| 周五下午 | 回顾 + 写周报 | 一键汇总本周任务 + 实验 → 周报草稿 |
| 学期末 / 节点前 | 对照检查 | 里程碑进度 + 毕业要求对照表 |

### 2.3 设计原则（个人工具能否用下去取决于此）

1. **30 秒原则**：任何一条记录（任务/实验/报销）的录入时间超过 30 秒，这条记录就不会被记下来。表单默认值、快捷键、速记语法都为这条服务。
2. **可补录**：漏记是常态，所有记录允许改日期补录，不设任何惩罚。
3. **DDL 至上**：不可移动的外部死线在所有视图中置顶并倒计时显示；任务排序默认按"是否服务于最近的 DDL"。
4. **索引不搬运**：文献交给 Zotero，文件交给本地文件夹，实验数据留在服务器。系统只登记"在哪 + 是什么"，绝不要求上传本体。
5. **数据自持**：SQLite 单文件 + 每日自动备份 + 全量导出，任何一天放弃使用也能带走全部数据。

### 2.4 与现有工具的分工

| 事务 | 用什么 | 系统为何不做 |
|---|---|---|
| 文献存储/批注/BibTeX | Zotero | 成熟工具，系统只做阅读清单联动 |
| 文件存储 | 本地/网盘文件夹 | 单人场景文件夹足够，系统登记路径即可 |
| 实验数据本体 | 实验室服务器/移动硬盘 | 数据量大格式杂，系统只记索引 |
| 即时沟通 | 微信/钉钉 | 不替代 |
| **科研事务总管** | **本系统** | — |

### 2.5 毕业时间线（已确认）

- 入学：**2027 年秋**；直博学制 **5 年** → 预计毕业：**2032 年 6 月**；
- 当前（2026-10 ~ 2027-09）处于**入学前阶段**：若已进组参与科研，先用"课题容器 + DDL"承接日常工作，学位里程碑按下方默认模板占位，入学后按培养方案校准；
- 毕业成果要求**尚未确定**：对照表（见 4.9）设计为可空、可随时增删改，发布前保持空白占位，不影响其他功能。

默认学位里程碑模板（**仅为常见五年直博节奏的参考，全部可编辑**，以本校培养方案为准）：

| 节点 | 参考时间 | 说明 |
|---|---|---|
| 入学、定导师与方向 | 2027-09 | — |
| 课程修读 + 文献综述 | 2027-09 ~ 2028-06 | 第一学年 |
| 资格/转段考核（如学院设置） | 2028 下半年 ~ 2029 | 按学院要求 |
| 开题 | 2029 年前后 | 直博一般在第 2~3 学期末 |
| 中期考核 | 2030 ~ 2031 | 第 3~4 学年 |
| 成果与论文主体冲刺 | 2031 ~ 2032 年初 | 毕业要求成果宜在此前基本完成 |
| 预答辩 → 送审/盲审 | 2032 年春 | — |
| 答辩 | 2032-05 ~ 06 | 预计毕业 |

## 3. 用户与部署形态

- **单用户**：简单口令登录（防本机他人误入），不做注册、角色、权限体系；
- 运行于本机 localhost；**仅做电脑端**，不考虑手机/移动端访问；
- **为将来留路**：所有数据实体保留 `owner` 字段与软删除标记。将来若"目前而言"兑现、推广给课题组，可平滑升级为 v0.1 存档版描述的多用户形态，无需推翻重来。

优先级：**P0 = MVP 必须**，**P1 = 第一批增强**，**P2 = 可选扩展**。标注【工科】的为工科博士生特色需求。

| 模块 | 优先级 |
|---|:---:|
| 4.1 课题（项目）管理 | P0 |
| 4.2 任务与收件箱 | P0 |
| 4.3 里程碑与 DDL 中心 | P0 |
| 4.4 实验记录【工科】 | P0 |
| 4.5 个人仪表盘 | P0 |
| 4.6 周报/组会助手 | P0 |
| 4.7 数据备份与导出 | P0 |
| 4.8 论文投稿流水线 | P1 |
| 4.9 成果库与毕业要求对照【工科】 | P1 |
| 4.10 报销垫付流水【工科】 | P1 |
| 4.11 文献阅读清单 | P1 |
| 4.12 资料索引 | P1 |
| 4.13 统计回顾 | P1 |
| 4.14 扩展能力 | P2 |

### 4.1 课题（项目）管理（P0）

- 建档字段：名称、类型（学位课题 / 导师纵向 / 横向 / 自选 / 申报事项）、我的角色（负责人/核心参与/参与）、起止时间、导师与合作者（纯文本备注）、备注；
- 状态四态：进行中 / 暂停 / 已结题 / 归档（归档只读）；
- 课题详情页：概要 + 该课题下任务、实验、文献、资料、报销的**聚合时间线**；
- 首页课题卡片：显示各课题近期动态与任务完成进度。

### 4.2 任务与收件箱（P0）

- **快速录入**：全局快捷键呼出，支持 `日期 + 事项 + #课题 + !优先级` 速记语法，回车即存；
- **收件箱**：未归类任务暂存，周五回顾时批量归入课题；
- 任务字段：标题、备注、所属课题（可空）、所属里程碑（可选）、优先级、截止日期、状态（待办/进行中/完成/放弃）；
- 视图：今日 / 本周 / 看板（按状态）/ 按课题分组；
- **重复任务**：如"每周组会 PPT"按周期自动生成；
- 完成的任务默认折叠但**永久可查**——它是周报和学期总结的数据来源。

### 4.3 里程碑与 DDL 中心（P0）

- 学位里程碑：自定义阶段（开题/中期/预答辩/送审/答辩/自定义）、目标日期、关联课题与任务；完成后标记，仪表盘常驻倒计时；
- DDL 条目：名称、类别（会议截稿 / 期刊返修 / 奖学金 / 竞赛 / 答辩窗口 / 其他）、日期、备注、提醒提前量（默认提前 7/3/1 天）；
- **时间轴视图**：未来 90 天所有节点一条轴；已过期未处理的红色置顶；
- DDL 可关联任务（"为这个死线要完成的事"）；
- 会议截稿年年有：支持复制生成下一年条目。

### 4.4 实验记录（P0）【工科】

- 字段（全部可选、30 秒可完成）：日期、所属课题、实验目的/方案（一句话）、关键参数与条件、样品/设备编号（可选）、**数据存放路径**（本地/服务器路径或 URL）、结果结论、后续待办（可一键转为任务）；
- 时间线视图 + **全文搜索**（事后能搜到"上次那个 XX 参数"）；
- 支持补录与修改（原则 2）；
- 与任务、周报联动：本周实验自动进入周报草稿；
- 不上传数据本体，只存索引（原则 4）。

### 4.5 个人仪表盘（P0）

- 今日待办（逾期红色置顶）；
- 倒计时区：学位里程碑 + 未来 30 天 DDL；
- 课题卡片：进度与最近动态；
- 本周小结：已完成任务数、实验次数（自动统计）。

### 4.6 周报/组会助手（P0）

- **一键生成**：拉取本周完成任务 + 实验记录 + 下周计划（从待办中勾选）→ Markdown 草稿，可编辑；
- 导出：复制到剪贴板 / 导出 .md / 打印（贴进组会 PPT）；
- 组会记录：日期、汇报要点、**导师意见**（自由文本，记下来防止忘）；
- 历史周报存档可检索。

### 4.7 数据备份与导出（P0）

- SQLite 单文件；每日定时自动备份到指定目录，保留最近 N 份（默认 30）；
- 一键全量导出：JSON（机器可读）+ Markdown（人类可读）；
- 支持从备份文件恢复。

### 4.8 论文投稿流水线（P1）

- 论文条目：题目（可用暂定名）、目标期刊/会议、当前阶段、稿件版本备注；
- **流水线看板**：构思 → 撰写中 → 组内审 → 投稿中 → 审稿中 → 返修 → 录用 → 见刊（阶段可自定义）；
- 日期跟踪：投稿日期、预计放榜时间（自动进入 DDL 中心）、返修 DDL；
- 超过预计审稿周期未见消息 → 标记"该催了"；
- 录用后自动写入成果库（4.9）。

### 4.9 成果库与毕业要求对照（P1）【工科】

- 成果条目：类型（期刊/会议论文、专利、软著、获奖）、题目、本人作者排序、状态、日期、DOI/链接、支撑课题；
- 毕业要求配置：学院要求条目化（如"SCI ≥1 篇"），支持自定义；**要求尚未发布时保持空白占位**，条款随时可增删改并备注依据（如培养方案/学位细则的文件名与版本）；
- **对照视图**：要求 vs 已有成果，标出缺口与"在途"（投稿中的论文按预期折算显示）；
- 一键导出个人成果清单（奖助申报、年度总结用）。

### 4.10 报销垫付流水（P1）【工科】

- 记录：日期、金额、事由、关联课题、状态（**垫付中 → 已提交 → 已到账/部分到账**）；
- 汇总"当前垫付未回款合计 ¥X"——工科生垫钱买耗材是常态，这笔账最容易被忘；
- 按课题统计个人经手开销。

### 4.11 文献阅读清单（P1）

- 字段：标题、作者/年份、标签、状态（想读/在读/已读）、一句话笔记、链接（Zotero/DOI/PDF 路径）、关联课题；
- 明确不做：PDF 存储、批注、BibTeX 管理（归 Zotero）。

### 4.12 资料索引（P1）

- 登记：名称、类型（申报书/报告/合同/数据集/代码仓库）、路径或 URL、所属课题、标签；
- 全局搜索统一检索任务、实验、资料。

### 4.13 统计回顾（P1）

- 周/月/学期视图：任务完成趋势、实验频次、按课题的投入分布（以记录条数近似）；
- "学期总结"自动拼装：本学期完成任务 + 实验 + 成果 → 草稿。

### 4.14 扩展能力（P2）

- 甘特图/时间线总览；
- iCal 订阅（手机日历直接看 DDL）；
- 移动端适配（当前仅电脑端，此条冻结，将来确有需要再启用）；
- Zotero API 联动；
- 时间追踪（番茄钟，统计各课题实际投入时长）；
- AI 辅助（实验记录摘要、周报润色）；
- 多用户化（启用 owner 字段，按 v0.1 存档版升级为课题组系统）。

## 5. 非功能需求

| 类别 | 要求 |
|---|---|
| 部署 | 本机运行（localhost），依赖最少、启动即用；仅电脑端 |
| 性能 | 本地单用户，页面秒开；全库搜索 ≤ 1 秒 |
| 账号 | 单用户口令登录即可，不做注册/找回（本地数据可从备份恢复） |
| 数据可靠 | 每日自动备份 + 手动导出双保险；备份保留 ≥ 30 份；恢复操作 ≤ 5 分钟 |
| 数据自主 | 全量数据可随时导出为 JSON + Markdown，无供应商锁定 |
| 隐私 | 纯本地运行，无任何外部上传，离线可用 |
| 可扩展 | 实体带 owner 字段与软删除，为课题组化预留 |
| 兼容 | Chrome/Edge 最新两个大版本；布局适配 1366×768 及以上（仅电脑端） |
| 可维护 | Git 管理；数据库结构变更脚本化（迁移脚本） |

## 6. 数据实体概要

- **User**（占位单用户）；**Project** 课题；**Task** 任务；**Milestone** 学位里程碑；**Deadline**（DDL 条目）；**ExperimentLog** 实验记录；**Paper** 论文；**Achievement** 成果；**GradRequirement** 毕业要求；**Expense** 报销；**Literature** 文献；**DocRef** 资料索引；**MeetingNote** 组会记录；**WeeklyReport** 周报；**Setting** 配置。

关系要点：

- Task / ExperimentLog / Literature / DocRef / Expense 均**可选**关联 Project（不强求归属）；
- Deadline 独立存在，可被 Paper（返修、放榜）、里程碑引用；
- Paper 录用后生成 Achievement；
- GradRequirement 与 Achievement 做多对多或按类型自动匹配对照。

详细字段与 ER 图在数据库设计阶段输出。

## 8. 技术选型建议

| 方案 | 组合 | 说明 |
|---|---|---|
| A（推荐） | FastAPI + SQLite + Vue 3（本地 Web） | 单文件数据库、部署简单、迭代快；将来可平滑升级 MySQL/多用户 |
| B | Tauri 桌面应用（打包 exe） | 双击即用体验最好，但迭代调试成本略高，适合 M4 后打包分发 |
| C | Django 全家桶 + 模板渲染 | 前端工作量最小，交互上限略低 |

推荐路径：方案 A 完成 M1–M3，系统稳定后再用 Tauri 打包成桌面应用。

|---|---|---|
| M1 · MVP（约 2–3 周） | 口令登录、课题、任务 + 收件箱 + 速录、DDL/里程碑中心、仪表盘 | **连续真实使用两周不弃坑** |
| M2 · 工科特色 | 实验记录、周报助手、自动备份 | 一次真实组会的周报完全由系统生成 |
| M3 · 完整版 | 论文流水线、成果对照、报销、文献、资料索引 | 毕业对照表实际可用 |
| M4 · 打磨 | 移动适配、日历订阅、统计、Tauri 打包 | 按需排期 |

> MVP 验收标准刻意写成"连续真实使用两周"——个人工具最大的失败模式不是做不出来，而是作者弃用。

## 11. 与 v0.1（课题组版）的差异说明

| 项 | v0.1 课题组版 | v0.2 个人版 | 理由 |
|---|---|---|---|
| 角色/权限 | 学生/导师/管理员 RBAC | 单用户口令 | 单人无需 |
| 审批流 | 立项/变更/结题审批 | 删除 | 无审批对象 |
| 项目状态机 | 7 态（含驳回、终止） | 4 态简化 | 课题定位为容器 |
| 导师视图/催交 | 有 | 删除（导师意见改为自由记录） | 无查看方 |
| 用户管理/批量导入 | 有 | 删除 | — |
| **实验记录** | P2（原计划不做） | **提升为 P0** | 工科单人核心工作单元 |
| **论文流水线、毕业对照** | 未单列（并入成果） | **单列，P1** | 博士个人主线 |
| 经费 | 课题组经费管理（科目/执行率） | 改为**个人垫付流水** | 视角从课题组经费转为个人垫付 |
| 周报 | 汇报提交/催交 | 改为**草稿生成器** | 无提交对象，生成给导师的草稿 |

v0.1 已存档为《需求报告-课题组版-存档.md》，将来推广时可作为升级蓝图直接启用。
